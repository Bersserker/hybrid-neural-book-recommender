# Итоговый проект: гибридная система рекомендаций книг с нейросетевыми моделями

Цель проекта — разработать систему рекомендаций книг, объединяющую классические подходы и нейросетевую архитектуру Two Tower, и сравнить качество отдельных моделей и их гибридов.

Основной прототип: [notebooks/prototype.ipynb](notebooks/prototype.ipynb). Этапы работы и требования описаны в [task.md](task.md).

## Компоненты системы

- **Popularity** — рекомендации на основе популярности книг в обучающей выборке.
- **Content-Based** — рекомендации по содержимому: TF-IDF представления названий и тегов книг.
- **Item-Based CF** — коллаборативная фильтрация на основе сходства книг по пользовательским взаимодействиям.
- **SVD** — матричная факторизация Surprise SVD для прогнозирования оценок по скрытым факторам пользователей и книг.
- **HybridRecommender** — объединение нормированных оценок базовых моделей с заданными весами.
- **AdaptiveHybridRecommender** — гибрид с весами, зависящими от активности пользователя.
- **TwoTowerRecommender** — нейросетевая модель с отдельными башнями пользователя и книги.
- **BalancedRecommender** — адаптивный гибрид с переранжированием MMR.

## Метрики качества

- **Precision@K** — доля релевантных книг среди первых K рекомендаций.
- **Recall@K** — доля найденных книг среди всех релевантных для пользователя.
- **nDCG@K** — качество ранжирования с учётом позиций релевантных книг: попадания в начале списка ценятся выше.
- **ILD@K** — среднее различие между книгами внутри выдачи, рассчитанное через косинусное сходство их контентных представлений.

Релевантными считаются книги с оценкой **4 или 5**. Метрики качества ранжирования усредняются по пользователям с релевантными книгами в выбранной выборке.

## Этап 1. Подготовка данных

Используется датасет Goodbooks-10k. Исходные файлы размещаются в `data/raw/`: `books.csv`, `ratings.csv`, `book_tags.csv`, `tags.csv`, `to_read.csv`.

После очистки взаимодействия каждого подходящего пользователя разделяются на три выборки в пропорции **60/20/20** с `random_state=42`:

- **train** — обучение моделей, расчёт признаков, популярности и истории прочитанного.
- **val** — выбор лучшей эпохи Two Tower по nDCG, подбор весов гибрида и параметра MMR. Градиенты Two Tower на val не рассчитываются.
- **test** — итоговая оценка после фиксации параметров. По результатам test параметры не подбираются.

### Расширенные признаки

| Уровень | Признаки |
| --- | --- |
| Пользователь | Число оценок, средняя оценка и стандартное отклонение (`ddof=0`), доля оценок ≥ 4, логарифм активности, сегмент активности, разнообразие жанров и доли жанров в положительной истории |
| Книга | Популярность, средняя и сглаженная оценка, стандартное отклонение, число разных оценок, нормированная энтропия распределения оценок, жанры и основной жанр |
| Пользователь–книга | Косинусное сходство с жанровым профилем, жанровая и авторская близость к положительной истории, разница средних оценок книги и пользователя |

Статистики строятся только по train. Для обучающих взаимодействий применяется **leave-one-out**: собственное взаимодействие исключается из агрегаций, включая глобальное среднее, жанровый профиль и историю автора. Для val, test и выдачи используются признаки полной train-истории.

Жанры определяются по словарю тегов; у книги может быть несколько жанров. Названия, авторы и агрегированные теги считаются общедоступными метаданными. Внешние рейтинги `books.average_rating` и внешние счётчики в признаки не включаются. При расчёте числа разных оценок и энтропии дробные рейтинги округляются до категорий 1–5; энтропия нормируется на `log(5)`.

## Этап 2. Построение классических гибридов

1. Объединяются четыре обученные модели: Popularity, Content-Based, Item-Based CF и SVD.
2. Оценки каждой модели приводятся к шкале от 0 до 1 и суммируются с весами. Отсутствие книги в кандидатах модели даёт нулевой вклад.
3. Кандидаты объединяются, уже прочитанные в train книги исключаются.
4. В адаптивном гибриде веса зависят от числа оценок пользователя: `new` — менее 5, `regular` — от 5 до 49, `active` — от 50.
5. MMR добавляет баланс между релевантностью и разнообразием.

**MMR (Maximal Marginal Relevance)** при выборе следующей книги учитывает её оценку и сходство с уже выбранными рекомендациями. Чем сильнее штраф за сходство, тем разнообразнее выдача. Исходные оценки релевантности и оценки MMR сохраняются отдельно.

## Этап 3. Оценка и оптимизация

Адаптивные веса подбираются Optuna отдельно для каждого сегмента на validation. Параметр MMR выбирается по максимальному ILD при допустимом относительном снижении nDCG не более 2% по сравнению с выдачей без штрафа за сходство.

После настройки классические модели и гибриды сравниваются на test по Precision@K, Recall@K и nDCG@K. Для адаптивных вариантов дополнительно рассчитывается ILD. Отдельные таблицы и графики показывают качество внутри сегментов `new`, `regular` и `active`.

## Продвинутая часть. Two Tower и интеграция в гибрид

Пользовательская башня получает ID-эмбеддинг, статистики пользователя и жанровый профиль. Книжная башня получает ID-эмбеддинг, статистики книги и жанровые признаки. После объединения входов каждая башня использует `Linear → ReLU → Linear → L2`. Оценка пары — скалярное произведение нормированных векторов.

Модель обучается с **BPR loss**: оценка положительной книги должна быть выше оценки отрицательной. Отрицательные книги выбираются вне train-истории пользователя. Числовые признаки масштабируются `StandardScaler`, обученным только на train. Парные признаки близости сохраняются для анализа, но напрямую в независимые башни не передаются.

В ноутбуке показан график train loss по эпохам. Лучшая эпоха выбирается по validation nDCG и может не совпадать с минимумом train loss.

После обучения Two Tower добавляется пятой моделью в существующую схему гибрида. Для нового состава повторно подбираются адаптивные веса и MMR на val. Классические экземпляры и результаты сохраняются для сравнения с нейросетевыми вариантами на том же test.

Улучшение от Two Tower проверяется по результатам эксперимента. Если существенного прироста нет, это само по себе не доказывает, что датасет слишком мал или специально подходит классическим моделям: для объяснения нужны дополнительные эксперименты с параметрами, признаками и объёмом обучения.

## Установка и запуск

Все команды выполняются из корня репозитория. Требуются **Python 3.12+**, **uv** и, для команд `make`, установленный Make.

### Установка зависимостей

Через Make:

```bash
make install
```

Напрямую через uv:

```bash
uv sync --no-install-project
```

Модули запускаются прямо из репозитория. Make использует `uv run --no-sync python`; после изменения зависимостей повторите установку.

### Сквозной пайплайн

Пайплайн запускается через `src/pipeline.py` и использует `run_pipeline` из `src/workflow.py`. Все шаги выполняются модулями `src/data/`, `src/models/` и `src/metrics/`; ноутбук для запуска не требуется и не читается.

Пайплайн выполняет загрузку CSV, очистку и разбиение, построение признаков, обучение, настройку на val, генерацию рекомендаций и итоговую test-оценку с отчётом по сегментам. Отдельный вызов подготовки данных перед ним не требуется.

Через Make:

```bash
# Скачать Goodbooks-10k, если исходные CSV ещё не подготовлены
make data

# Проверить всю цепочку на 200 пользователях
make pipeline-smoke

# Полный запуск с Two Tower
make pipeline

# Запуск классических моделей и гибридов без Two Tower
make pipeline-classical
```

Эквивалентные примеры через uv:

```bash
uv run --no-sync python -m src.data.make_dataset

uv run --no-sync python -m src.pipeline \
  --max-users 200 --epochs 2 --svd-epochs 5 --n-trials 3 \
  --tuning-users 100 --eval-users none \
  --output-dir artifacts/notebook_pipeline_smoke

uv run --no-sync python -m src.pipeline

uv run --no-sync python -m src.pipeline --no-neural \
  --output-dir artifacts/notebook_pipeline_classical
```

Можно скачать данные внутри пайплайна: `make pipeline DOWNLOAD=1` или `uv run --no-sync python -m src.pipeline --download`.

Для своих данных и параметров:

```bash
make pipeline RAW_DATA_DIR=/path/to/csv \
  PIPELINE_OUTPUT_DIR=artifacts/experiment \
  MAX_USERS=1000 EPOCHS=10 N_TRIALS=50 DEVICE=cpu RECOMMEND_USERS=1,2,3

uv run --no-sync python -m src.pipeline \
  --data-dir /path/to/csv --output-dir artifacts/experiment \
  --max-users 1000 --epochs 10 --n-trials 50 --device cpu \
  --recommend-user-ids 1,2,3
```

Основные параметры:

| Make | Параметр CLI | По умолчанию |
| --- | --- | --- |
| `MAX_USERS` | `--max-users` | `none`, все пользователи |
| `TUNING_USERS` | `--tuning-users` | `200` |
| `EVAL_USERS` | `--eval-users` | `none`, все подходящие test-пользователи |
| `EPOCHS` | `--epochs` | `5` |
| `SVD_EPOCHS` | `--svd-epochs` | `50` |
| `N_TRIALS` | `--n-trials` | `30` на сегмент |
| `BATCH_SIZE` | `--batch-size` | `1024` |
| `K` | `--k` | `10` |
| `CANDIDATES_K` | `--candidates-k` | `100` |
| `RANDOM_STATE` | `--random-state` | `42` |
| `THREADS` | `--threads` | `2` |
| `DEVICE` | `--device` | Автоматический выбор |

Для ограничений числа пользователей `none` или `all` означает отсутствие ограничения. Проверочный запуск на подвыборке служит для проверки цепочки; итоговые выводы следует соотносить с фактическим размером эксперимента.

### Отдельные этапы: подготовка, обучение, отчёт

В отличие от сквозного пайплайна, отдельная команда обучения требует заранее подготовленных файлов в `data/processed/`.

Через Make:

```bash
make prepare_data
make train
make report SPLIT=test

# Обучение и отчёт для одной модели
make train-two_tower EPOCHS=10 DEVICE=cpu
make report-two_tower SPLIT=test

# Обучение и отчёт одной командой; отчёт по умолчанию на val
make train-report MODEL=adaptive N_TRIALS=50
```

Через uv:

```bash
uv run --no-sync python -m src.data.prepare_data
uv run --no-sync python -m src.models.train --model all --epochs 5 --n-trials 30
uv run --no-sync python -m src.metrics.report --model all --split test --k 10

uv run --no-sync python -m src.models.train --model two_tower --epochs 10 --device cpu
uv run --no-sync python -m src.metrics.report --model two_tower --split test

uv run --no-sync python -m src.models.train --model adaptive --n-trials 50
uv run --no-sync python -m src.metrics.report --model adaptive --split val
```

Доступные значения `MODEL` / `--model`: `pop`, `content`, `item`, `svd`, `two_tower`, `hybrid`, `adaptive`, `balanced`, `all`. Для каждой отдельной модели есть цели `make train-<модель>` и `make report-<модель>`. Отчёт требует соответствующих сохранённых артефактов; для `all` нужны все восемь моделей.

### Работа с ноутбуком

```bash
uv run --no-sync jupyter lab notebooks/prototype.ipynb
```

## Результаты и повторный запуск

Сквозной запуск по умолчанию сохраняет результаты в `artifacts/notebook_pipeline/`:

- `processed/` — разбиения `train.csv`, `val.csv`, `test.csv`;
- `reports/report.md` — итоговый отчёт;
- `reports/metrics.csv`, `reports/segments.csv` — общие и сегментные метрики;
- `reports/recommendations.csv` — примеры рекомендаций с названиями книг;
- графики метрик, история обучения Two Tower, результаты подбора весов, выбранные параметры и `config.json`.

Проверочный и классический запуски используют суффиксы `_smoke` и `_classical`. Путь меняется через `PIPELINE_OUTPUT_DIR` или `--output-dir`. Функция `run_pipeline` создаёт собственные экземпляры моделей и возвращает итоговую модель в памяти.

Отдельное обучение через `src.models.train` сохраняет модели в `artifacts/*.joblib`, историю Two Tower — в `artifacts/two_tower_history.csv`, результаты Optuna — в `artifacts/adaptive_weight_search.csv`. Отчёты отдельной команды размещаются в `reports/<val|test>/<модель|all>/`.

Пример загрузки сохранённой модели:

```python
import joblib

model = joblib.load("artifacts/adaptive_hybrid_recommender.joblib")
recommendations = model.recommend(user_id=1, N=10)
```

Рекомендации содержат `book_id` и `score`; у MMR также есть `mmr_score`. Прочитанные в train книги исключаются. Повторный запуск с теми же путями обновляет результаты; для отдельных экспериментов задавайте разные выходные папки.
